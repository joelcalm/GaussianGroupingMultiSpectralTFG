# Vinyes 20260509 Pinhole Hybrid Object Experiment

Date: 2026-06-05

## Objective

This experiment tested an all-object supervision setup for `vinyes_20260509_pinhole` while preserving the manually corrected identities for the two target vines across the 31 selected correction frames.

The previous compact `final_15` ground truth only evaluated the corrected target vines and left other SAM3/tracked objects black. The hybrid setup keeps those compact masks as a target-vine-only evaluation, but uses a new all-object mask set for training and broader comparison.

The corrected target IDs were intentionally moved out of the existing SAM3 ID range:

| ID | Label |
|---:|---|

## Key Lessons

The missing non-target vines in the previous `final_15` images came from GT construction, not from rendering. The compact eval masks intentionally collapsed the task down to the curated target vines, leaving other objects black.

The hybrid masks fix that by starting from the full SAM3/tracked reference masks, then overwriting only the corrected target IDs. This gives two useful evaluation views: all-object quality and target-vine-only quality.

Color mismatch in rendered `objects_pred` images is mostly visualization, not necessarily identity failure. The model predicts object indices, and colorization can use a different palette than SAM3 masks unless predictions are remapped through the GT legend. The metrics use label/index matching rather than raw visual color similarity.

All-object metrics are much harsher than target-compact metrics because they include many small, fragmented, and less manually curated SAM3 tracks. This is expected and makes all-object results better for broad segmentation quality, while compact results are better for checking the two corrected vine identities.

`rgb` is the strongest overall variant here. It wins all-object mIoU/Dice-F1 and compact target mIoU/Dice-F1. `rgb_ms` has the best compact target pixel accuracy, but does not improve overlap-based object quality, so the added MS photometric channels are not clearly helping object identity in this configuration.

The first `rgb_ms` run exposed a wrapper weakness: training can stop before the first save iteration and the shell script will still print a "finished" line. Future long runs should check that `point_cloud/iteration_$ITERATIONS/point_cloud.ply` exists before rendering or evaluating.

## Recommended Next Steps

1. Add a checkpoint-existence guard to the experiment wrapper after each training run.
2. Keep early save points for expensive variants, at least `5000`, `10000`, `20000`, `30000`, and final.
3. Review the six A/B leaf conflicts in `target_id_mapping_template.csv`.
4. Use `final_15_all_objects` for all-object training/comparison and keep compact `final_15` as the focused target-vine sanity check.
5. For visual inspection, always colorize predictions through the same GT legend/mapping used by the evaluator.
